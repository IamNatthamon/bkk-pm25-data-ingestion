## STEP 7 — Pipeline Manifest

**Current** `data/gold/model_ready/pipeline_manifest.json`:

- **Top-level keys:** `pipeline_version`, `created_at`, `config`, `splits`, `features`.
- **Does not contain:** `feature_cols`, `target_col`, `sequence_length`, `num_features`.
- **Feature list:** under `features.columns` (51 entries), including the 4 placeholder hotspot columns.

**Implication:** `notebooks/modeling/model_training.ipynb` expects `MANIFEST["feature_cols"]` and `MANIFEST["target_col"]`. With the current manifest, **training notebook would raise KeyError** unless the code is adapted to read `features.columns` and to infer target/sequence length elsewhere.

---

## STEP 8–9 — Model Input Features and Tensor

- **Feature loading:** Model training uses `FEATURE_COLS = MANIFEST["feature_cols"]` and builds `sdf[feature_cols].values` for each sequence → shape `(seq_len, num_features)`.
- **Current gold + current manifest:** If one uses `features.columns` as the feature list, the model receives 51 features including 4 hotspot columns, but those 4 columns are **all NaN** in the parquet files. Sequences with NaN in any feature are **skipped** by `PM25SequenceDataset` (`if np.isnan(x).any() or np.isnan(y).any(): continue`), so effectively the model is trained on a subset of data and the “hotspot” dimensions carry no information.

**Conclusion:** With current gold data, **hotspot features do not affect the model** (either unused or constant NaN).

## STEP 12 — Root Cause and Recommendations

### Root cause

1. **Gold and manifest** in `data/gold/model_ready/` were produced by a **different pipeline** (e.g. gold layer with different schema and manifest format).
2. **Preprocessing notebook** was updated to integrate **32 real hotspot features** from `src/hotspot_features.py`, but has **not** been run to regenerate gold and manifest.
3. **Model training** expects manifest keys `feature_cols`, `target_col`, `sequence_length`; current manifest does not provide them, so training would fail or require code changes to use `features.columns`.

### Recommendations

1. **Re-run `preprocessing_pipeline.ipynb`** from project root so that:
  - Hotspot feature table is built from `data/bronze/raw_hotspot/` and merged into the daily table.
  - Train/val/test parquet and `pipeline_manifest.json` are overwritten with:
    - **32 hotspot columns** (hotspot_thailand, …, hotspot_china_yunnan, *_lag1, *_lag2, *_lag3).
    - Manifest containing **feature_cols**, **target_col**, **sequence_length**, **num_features**.
2. **Verify after re-run:**
  - `train.parquet` has 32 columns whose names start with `hotspot_`.
  - Those columns are numeric and not all NaN.
  - `pipeline_manifest.json` has top-level `feature_cols` and lists all 32 hotspot features.
3. **Run `notebooks/modeling/model_training.ipynb`** again; it will then load the new manifest and use the new feature list, including hotspots, in the input tensor.
4. **Re-run correlation and feature importance** (e.g. SHAP) on the new gold to confirm hotspot–PM2.5 relationship and model use of hotspot features.
